用 tech-spec skill,读已批准的 `spec.md` 与设计稿,一步做完技术方案与排期:

1. 自主 WebSearch + GitHub 调研,逐个功能给出选型结论与理由(带真实链接、star、最近提交、license),不要把候选原样丢给我挑。
2. 出架构与 ADR、`data-model.md`、`contracts/`,自己过四维闸门自检。
3. 停在**确认门 1**:用大白话讲清这个方案解决什么问题、每个关键选择为什么这么选、零用户与一千日活两档月成本、有什么风险和取舍。等我点头。
4. 点头后拆 `tasks.md`(单一动作 + 精确文件路径 + 能跑的完成判据 + 回指 AC)与 `plan.md`(批次 + `[P]` 并行 + 关键路径),并为每个可并行批次排出 worktree 执行清单(目录 / 分支 / 文件集合 / 任务 / 判据 / 合并顺序);先探当前平台的隔离与并发能力,探不到就降级串行并明说。跑机器自检。
5. 停在**确认门 2**:讲清总共几批几个任务、哪些能同时开工、排了几条并行线各动哪些文件、每步做完我能验到什么。等我点头才移交开发,worktree 你自己建自己合,别让我敲 git 命令;合并冲突停下来问我。
